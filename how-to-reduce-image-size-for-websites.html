How to Reduce Image Size for Websites

Published August 2026 · 6 min read

Every image on a web page has a physical display size — the number of pixels it actually occupies on screen. Yet it's astonishingly common for a source file to be uploaded at three or four times that size, forcing every visitor's browser to download pixels it's just going to throw away. Fixing this is one of the highest-leverage, lowest-effort changes you can make to a website.

Match dimensions to actual display size, not camera resolution

A modern phone or camera can easily produce a 4000px-wide photo. If that image is placed in a blog post column that renders at 800px wide, roughly 95% of the downloaded pixel data was wasted — the browser scales it down after the full file has already loaded. Before uploading anything to a CMS, check how wide the image will actually display, and resize the source file to match.

The retina multiplier

High-density "retina" screens pack more physical pixels into the same space, so sizing an image at exactly its display width can look slightly soft on those screens. The fix isn't to upload at full camera resolution — it's to size the source at roughly 1.5–2x its maximum display width. An image shown at 800px wide only needs to be about 1200–1600px as a source file to look crisp everywhere, without the bloat of an unnecessarily huge original.

Practical targets by placement

  • Hero / banner images: around 1920×1080px
  • Blog post / article images: around 1200×800px
  • Product or content thumbnails: 400×400 to 600×600px
  • Avatars and small icons: 128×128 to 256×256px

These are sensible starting points, not hard rules — the correct number always depends on your specific layout — but they're a solid default if you don't already have exact numbers to work from.

Format and quality still matter after resizing

Correct pixel dimensions solve half the problem. The other half is format and compression: WEBP is generally the best default for web photos today, JPEG remains a safe fallback, and PNG stays reserved for graphics and transparency. Combine correctly-sized dimensions with a quality setting around 75–85% for the best balance of sharpness and page weight — for more detail on picking a quality number, see our guide on compressing images without losing quality.

A repeatable resizing workflow

  1. Decide the maximum width the image will actually render at in your layout.
  2. Multiply by 1.5–2x to account for high-density screens.
  3. Resize the source image to that width, keeping the aspect ratio locked.
  4. Compress at 75–85% quality in JPEG or WEBP.
